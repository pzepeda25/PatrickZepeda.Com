# SOP: HyperFrames — Local setup → composition → lint → render

**Repo:** This file is the **canonical** version for [PatrickZepeda.Com](https://github.com/pzepeda25/PatrickZepeda.Com) (`docs/SOP-HyperFrames-From-Zero-To-Render.md`). Commit changes here and push so they travel with your personal brand repo.

**Purpose:** One repeatable path from an empty tree on your Mac to a valid HyperFrames project, preview, clean lint, and exported video.

**Conventions in this SOP**
- **Parent folder:** `~/Documents/HyperFrames/` (all HyperFrames composition projects live here — outside this repo).
- **Example project name:** `my-project` — replace with your real folder name (e.g. `brand-video-lab`).
- **This React / Netlify site** is separate; it only **stores this SOP** for your workflow. HyperFrames lab projects are not submodules of this repo unless you add them yourself.

**References (official / bundled in projects)**
- App docs: [hyperframes.heygen.com/introduction](https://hyperframes.heygen.com/introduction)
- LLM index: [hyperframes.heygen.com/llms.txt](https://hyperframes.heygen.com/llms.txt)
- In any HF project, read `AGENTS.md` in that project root for commands and structure.

## Phase 0 — One-time: Node and CLI

1. Install **Node.js** (LTS) if you don’t have it: [https://nodejs.org](https://nodejs.org)
2. You will use the CLI **without global install** via `npx` (e.g. `npx hyperframes …`). No global `npm i -g` required for this SOP.

## Phase 1 — Folder layout (Documents → HyperFrames → project)

### 1.1 Create the parent `HyperFrames` directory

In Terminal:

```bash
mkdir -p ~/Documents/HyperFrames
cd ~/Documents/HyperFrames
```

This folder is your **lab root**: one subfolder = one video composition project.

### 1.2 Create a new project folder and standard subfolders

```bash
# Choose a name (kebab-case is fine)
export PROJECT=my-project
mkdir -p "$PROJECT"/{compositions,assets,output,renders}
cd "$PROJECT"
```

**Standard layout (must-haves for a typical project)**

| Path | Role |
|------|------|
| `index.html` | Main composition (root timeline). |
| `compositions/` | Sub-compositions; referenced with `data-composition-src` from root or each other. |
| `compositions/components/` | Optional, if you use shared “components” (see `hyperframes.json` below). |
| `assets/` | Video, audio, images, fonts, etc. |
| `output/` | Optional: intermediate or exported side files (your convention). |
| `renders/` | Usual place for `hyperframes render` outputs (or whatever path you set in the CLI). |
| `hyperframes.json` | Wires `paths.blocks`, `paths.components`, `paths.assets` to the folders above. |
| `meta.json` | Project id, name, and metadata. |

**Optional (often created as you go)**  
- `.thumbnails/` — auto-generated by tooling in some flows  
- `transcript.json` — if you add Whisper / transcript pipeline  

### 1.3 Add `hyperframes.json` (path wiring)

At `~/Documents/HyperFrames/<PROJECT>/hyperframes.json`:

```json
{
  "$schema": "https://hyperframes.heygen.com/schema/hyperframes.json",
  "registry": "https://raw.githubusercontent.com/heygen-com/hyperframes/main/registry",
  "paths": {
    "blocks": "compositions",
    "components": "compositions/components",
    "assets": "assets"
  }
}
```

Create the `components` directory if you use it:

```bash
mkdir -p compositions/components
```

### 1.4 Add `meta.json`

Example `~/Documents/HyperFrames/<PROJECT>/meta.json`:

```json
{
  "id": "my-project",
  "name": "My Project",
  "createdAt": "2026-01-01T00:00:00.000Z"
}
```

### 1.5 Minimal `index.html` starter

- Start from an official or team template if you have one.  
- Otherwise create a **minimal** `index.html` that loads the HyperFrames runtime the way your template does (see docs or copy from an existing good project like `brand-video-lab`).

**Do not** rely on hand-rolled `video.currentTime` / ad-hoc `play()` for things the framework is supposed to schedule — the linter will flag **`imperative_media_control`**. Use **`data-start`**, **`data-duration`**, and media alignment attributes (e.g. `data-media-start` / `data-playback-start` per docs) so preview, timeline, and renders stay deterministic.

## Phase 2 — Agent skills (recommended before heavy editing)

From the project root `~/Documents/HyperFrames/<PROJECT>`:

```bash
npx skills add heygen-com/hyperframes
```

This installs patterns (timelines, `data-*` semantics, shader-friendly CSS) so agents and you don’t fight the framework.

## Phase 3 — Day-to-day workflow (edit → preview → lint)

Always run commands from **`~/Documents/HyperFrames/<PROJECT>`** (where `index.html` and `hyperframes.json` live).

### 3.1 Preview (studio / browser)

```bash
npx hyperframes preview
```

Use this to scrub timing and see the composition as the engine expects.

### 3.2 Lint (required before you call a scene “done”)

```bash
npx hyperframes lint
```

For automation or JSON consumers:

```bash
npx hyperframes lint --json
```

**Policy:** fix **all errors**; treat **warnings** per project rules. Your project’s `AGENTS.md` may say: run lint after every HTML change and fix errors before handoff.

**Common error:** `imperative_media_control` — remove inline scripts that set `currentTime` or imperatively play/pause managed media; express timing with HyperFrames’ declarative attributes instead.

### 3.3 Project rules to keep lint green (from `AGENTS.md` patterns)

1. **Timing:** use **`data-start`**, **`data-duration`**, and **`data-track-index`** on timed elements as required by your project/docs.
2. **Visibility:** visible timed elements should use **`class="clip"`** where the framework expects it.
3. **GSAP:** timelines **`paused: true`**, registered on:
   - `window.__timelines = window.__timelines || {}`
   - `window.__timelines["composition-id"] = gsap.timeline({ paused: true })`
4. **Video + audio:** prefer **`video` muted** + separate **`<audio>`** for sync, per your house rules.
5. **Sub-compositions:** `data-composition-src="compositions/foo.html"`.
6. **Determinism:** avoid **`Date.now()`**, **`Math.random()`**, and **network fetches** in code paths that affect output.

### 3.4 Docs in terminal (optional)

```bash
npx hyperframes docs <topic>
```

## Phase 4 — Render (export video)

From the same project root:

```bash
npx hyperframes render
```

- Confirm **output path** in CLI output; often under **`renders/`** or a path you pass if the CLI supports it — check `npx hyperframes render --help` for flags.
- Keep **`output/`** or **`renders/`** in `.gitignore` if these folders are large and the repo is public (optional; depends on your Git policy).

## Phase 5 — Optional: version control

If you use Git:

```bash
cd ~/Documents/HyperFrames/<PROJECT>
git init
# add a sensible .gitignore: node_modules, .thumbnails, large mp4, etc.
```

Push to a remote when you want backup or team review. HyperFrames does not require Git for local preview or render.

**This personal brand repo** is a natural place to **store this SOP** only; your HyperFrames compositions can stay in `~/Documents/HyperFrames/` or in their own Git repos as you prefer.

## Phase 6 — Quick “new project from scratch” checklist

Use this as a copy-paste checklist for each new folder under `~/Documents/HyperFrames/`:

- [ ] `mkdir -p ~/Documents/HyperFrames/<name>/{compositions,assets,output,renders,compositions/components}`
- [ ] Add `hyperframes.json` (paths as above)
- [ ] Add `meta.json` (id + name)
- [ ] Add or copy `index.html` + any starter `compositions/*.html`
- [ ] `npx skills add heygen-com/hyperframes` (once per project or refresh as needed)
- [ ] `npx hyperframes preview` — confirm it opens
- [ ] `npx hyperframes lint` — 0 errors before locking a milestone
- [ ] `npx hyperframes render` — produced file lands where you expect
- [ ] If applicable: `git init`, `.gitignore`, push to remote
- [ ] If you change this **SOP**: edit **`docs/SOP-HyperFrames-From-Zero-To-Render.md`** in **PatrickZepeda.Com** and push
